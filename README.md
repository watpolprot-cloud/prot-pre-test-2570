# ระบบรับสมัครสอบ PRE PROT TEST 2570 — โรงเรียนพรตพิทยพยัต

ระบบรับสมัครสอบออนไลน์ของกิจกรรม PRE PROT TEST 2570 (สอบวันอาทิตย์ที่ 24 มกราคม 2570 · ค่าสมัคร 99 บาทต่อคน)
ดูแลโดย ทีมงานวัดผลและประเมินผล โรงเรียนพรตพิทยพยัต

| สนามสอบ | ผู้สมัคร | เลขที่สมัคร |
|---|---|---|
| ลองสนามสอบเข้า ม.1 | ป.5–ป.6 | P700001, P700002, ... |
| ลองสนามสอบเข้า ม.4 | ม.3 | M700001, M700002, ... |

## ส่วนประกอบ

| ส่วน | อยู่ที่ | หน้าที่ |
|---|---|---|
| ใบสมัคร `apps-script/Index.html` | Google Apps Script (ลิงก์ลงท้าย `/exec`) | ลิงก์และ QR Code บนโปสเตอร์ ผู้ปกครองกรอกใบสมัคร 1–5 คนต่อครั้ง แนบสลิป |
| ตัวกลาง `apps-script/Code.gs` | Google Apps Script ผูกกับ Google Sheet | บันทึกใบสมัคร ตรวจสลิป กระทบยอด จัดที่นั่ง คิดคะแนน และเป็น API ให้เว็บไซต์ |
| ฐานข้อมูล | Google Sheet + โฟลเดอร์สลิปใน Google Drive ของบัญชีที่ติดตั้ง | ข้อมูลผู้สมัครทั้งหมดอยู่ที่นี่เท่านั้น |
| เว็บไซต์ `index.html` | GitHub Pages (repo นี้) | กำหนดการ ระเบียบการสอบ วิธีสมัคร และเข้าระบบดูสถานะ ที่นั่งสอบ บัตรเข้าสอบ ผลสอบ |

`config.js` เก็บลิงก์เว็บแอป Apps Script ถ้าเว้นว่าง เว็บไซต์ทำงานในโหมดสาธิต (ข้อมูลตัวอย่าง)

`form-demo.html` เป็นสำเนาใบสมัครสำหรับดูตัวอย่างเท่านั้น ส่งใบสมัครจริงไม่ได้ (สร้างใหม่ด้วย `node dev/build-demo.js`)

repo นี้ **ไม่มีข้อมูลผู้สมัครรายบุคคล** และห้ามนำไฟล์ข้อมูลผู้สมัครมาใส่ใน repo

## ติดตั้งครั้งแรก

### 1. สร้าง Google Sheet และวางโค้ด
1. ใช้บัญชี Google ที่จะดูแลระบบ สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `PRE PROT TEST 2570 ระบบรับสมัคร (ฐานข้อมูล)`
2. เมนู **ส่วนขยาย → Apps Script**
3. ไฟล์ `Code.gs` ลบโค้ดเดิม แล้ววางเนื้อหา `apps-script/Code.gs`
4. กด **+ → HTML** ตั้งชื่อ `Index` (ไม่ต้องพิมพ์ .html) แล้ววางเนื้อหา `apps-script/Index.html`
5. **การตั้งค่าโปรเจกต์ (รูปเฟือง)** → ติ๊ก "แสดงไฟล์ Manifest appsscript.json ในตัวแก้ไข" → เปิดไฟล์ `appsscript.json` แล้ววางเนื้อหา `apps-script/appsscript.json`
   (ไฟล์นี้เปิดบริการ Drive API v3 ที่ใช้อ่านตัวอักษรบนสลิป ถ้าไม่วาง ให้กด **บริการ +** → Drive API → เวอร์ชัน v3 → ตัวระบุ `Drive`)
6. กดบันทึก

### 2. ตั้งค่าครั้งแรก
1. เลือกฟังก์ชัน `setup` แล้วกด **เรียกใช้** → อนุญาตสิทธิ์ (Sheets, Drive, Docs สำหรับ OCR, ส่งอีเมล)
2. กลับไปที่ Google Sheet จะมีแท็บครบ และมีเมนู **Pre Prot Test** (ถ้าไม่เห็นให้รีเฟรช)
3. ระบบสร้างโฟลเดอร์ `PreProtTest2570-สลิปโอนเงิน (ห้ามแชร์)` ใน Drive ของบัญชีนี้ ห้ามแชร์โฟลเดอร์นี้ให้บุคคลภายนอก

### 3. เปิดใช้เป็นเว็บแอป
1. ใน Apps Script กด **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → ประเภท: เว็บแอป**
2. ดำเนินการในฐานะ: **ฉัน** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน**
3. คัดลอกลิงก์ที่ลงท้ายด้วย `/exec` ลิงก์นี้คือลิงก์ใบสมัคร ใช้ทำ QR Code บนโปสเตอร์

> บัญชีโรงเรียน (@prot.ac.th) อาจไม่มีตัวเลือก "ทุกคน" เพราะผู้ดูแลระบบ Google Workspace ปิดไว้ ถ้าเป็นเช่นนั้น บุคคลภายนอกจะเปิดใบสมัครไม่ได้ ต้องขอผู้ดูแลระบบของโรงเรียนก่อน
>
> อีเมลยืนยันการสมัครส่งจากบัญชีที่ติดตั้ง และมีโควตาการส่งต่อวันตามประเภทบัญชีของ Google

### 4. เชื่อมเว็บไซต์ GitHub Pages
1. แก้ `config.js` ใส่ลิงก์ `/exec` ใน `apiUrl` แล้ว Commit + Push
2. ใน GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)**
3. นำลิงก์เว็บไซต์ (เช่น `https://<ชื่อบัญชี>.github.io/<ชื่อ repo>/`) ไปใส่ในแท็บ **ตั้งค่า** ช่อง `ลิงก์เว็บตรวจสถานะ (GitHub Pages)` ใบสมัครและอีเมลยืนยันจะมีลิงก์ไปเว็บไซต์

### 5. กรอกข้อมูลกิจกรรมในแท็บของ Google Sheet
ค่าที่ขึ้นว่า "รอยืนยัน" เป็นค่าร่างตามปี 2569 ต้องแก้ให้ตรงปี 2570 ก่อนเปิดรับสมัคร

| แท็บ | กรอกอะไร |
|---|---|
| ตั้งค่า | วันเริ่ม/สิ้นสุดรับสมัคร, จำนวนรับสูงสุดแต่ละสนาม, ช่องทางติดต่อ, คะแนนเต็มต่อวิชา แล้วตั้ง `เปิดรับสมัคร` = TRUE เมื่อพร้อม |
| ห้องสอบ | ห้องและความจุ (คน) ของแต่ละสนาม (ร่างไว้ตามห้องปี 2569) |
| กำหนดการ | รายการกำหนดการที่แสดงบนเว็บไซต์ |

## งานประจำวันช่วงรับสมัคร

1. **วางรายการเงินเข้า** ในแท็บ `รายการเงินเข้า` เฉพาะรายการฝากเข้า
   - `วันที่` เช่น `05/01/2570`, `5 ม.ค. 2570` หรือรูปแบบวันที่ของ Google Sheet
   - `เวลา` เช่น `10:15` หรือ `10.15`
   - `จำนวนเงิน` เช่น `198.00`
   - `รายละเอียด` ไม่บังคับ
2. เมนู **Pre Prot Test → กระทบยอดกับรายการเงินเข้า**
   ระบบจับคู่รายการที่ยอดเงินเท่ากันและเวลาในสลิปห่างจากเวลาเงินเข้าไม่เกิน 3 นาที (แก้ได้ที่ `เวลาคลาดเคลื่อนที่ยอมรับ (นาที)`)
   - จับคู่ได้รายการเดียว → เปลี่ยนเป็น "ยืนยันแล้ว" และเขียนเลขที่รายการลงคอลัมน์ `จับคู่กับรายการ`
   - มีหลายรายการที่เข้าเงื่อนไข หรือหาไม่พบ → แสดงในรายงานให้ตรวจเอง
3. รายการ **รอตรวจ** หรือที่จับคู่ไม่ได้: เปิดลิงก์สลิป อ่าน `รายละเอียดผลตรวจ` แล้วเลือกแถวในแท็บ `การชำระเงิน`
   - **ยืนยันการชำระเงิน (แถวที่เลือก)** เมื่อตรวจกับบัญชีแล้วว่าเงินเข้า
   - **ไม่ผ่าน (แถวที่เลือก)** แล้วพิมพ์ข้อความแจ้งผู้สมัคร เช่น "ยอดโอนไม่ครบ กรุณาโอนเพิ่ม 99 บาท และติดต่อเจ้าหน้าที่"
4. **ตรวจสลิปอัตโนมัติอีกครั้ง (แถวที่เลือก)** ใช้เมื่อแก้ไขการตั้งค่าแล้วต้องการให้ระบบตรวจใหม่
5. **สรุปยอดผู้สมัคร** แสดงจำนวนผู้สมัครแต่ละสนาม จำนวนคนแยกตามสถานะ และยอดเงินที่ยืนยันแล้ว

## ก่อนวันสอบ
1. กรอกความจุทุกห้องในแท็บ `ห้องสอบ`
2. เมนู **จัดที่นั่งสอบ (เพิ่มเฉพาะผู้ที่ยังไม่มีที่นั่ง)** จัดเฉพาะผู้ที่ "ยืนยันแล้ว" เรียงตามเลขที่สมัคร เลขที่นั่งเช่น `P0101` = สนาม ม.1 ห้องลำดับที่ 01 ที่นั่ง 01
   - กดซ้ำได้เมื่อมีผู้ยืนยันเพิ่ม คนที่มีเลขที่นั่งแล้วใช้เลขเดิม คนใหม่ได้ที่นั่งว่างถัดไป ผู้ที่สถานะไม่ใช่ "ยืนยันแล้ว" จะถูกล้างที่นั่ง
   - **จัดที่นั่งสอบใหม่ทั้งหมด (ก่อนประกาศ)** ล้างแล้วจัดใหม่ทั้งหมด ใช้เมื่อแก้ห้องหรือความจุก่อนประกาศเท่านั้น
3. ตั้ง `ประกาศที่นั่งสอบ` = TRUE ผู้สมัครจะเห็นเลขที่นั่ง ห้องสอบ และพิมพ์บัตรเข้าสอบได้จากเว็บไซต์

## หลังสอบ
1. กรอกคะแนนในแท็บ `ผลสอบ` (เลขที่สมัคร + คะแนนรายวิชา)
2. เมนู **คำนวณคะแนนรวมและอันดับ** (อันดับแยกตามสนามสอบ คะแนนเท่ากันได้อันดับเดียวกัน)
3. ตั้ง `ประกาศผลสอบ` = TRUE และถ้าต้องการแสดงอันดับกับป้าย TOP 10 ให้ตั้ง `แสดงอันดับในผลสอบ` = TRUE

## การตรวจสลิป (ไม่มีค่าใช้จ่าย)

| ลำดับ | สิ่งที่ตรวจ | วิธีตรวจ |
|---|---|---|
| 1 | สลิปซ้ำ | ลายนิ้วมือไฟล์ภาพ (SHA-256), ข้อความใน QR และเลขอ้างอิงธุรกรรม เทียบกับทุกรายการเดิม |
| 2 | QR Code บนสลิป | อ่านในเบราว์เซอร์ของผู้สมัคร ตรวจรูปแบบและรหัสตรวจสอบ (CRC) ของ QR สลิปธนาคารไทย อ่านรหัสธนาคารผู้โอนและเลขอ้างอิง |
| 3 | บัญชีผู้รับ ชื่อบัญชี ยอดเงิน วันเวลาโอน | อ่านตัวอักษรบนสลิปด้วย OCR ของ Google Drive แล้วเทียบกับเลขบัญชี 693-0-53838-8 (ซึ่งสลิปมักแสดงแบบปิดบางหลัก เช่น xxx-x-x3838-x), ชื่อ "เงินสวัสดิการโรงเรียนพรตพิทยพยัต", ยอด 99 × จำนวนผู้สมัคร และช่วงวันรับสมัคร |
| 4 | เงินเข้าบัญชีจริง | กระทบยอดกับแท็บ `รายการเงินเข้า` |

**ข้อจำกัด** การตรวจจากภาพสลิป (ข้อ 1–3) ไม่ว่าจะใช้ OCR หรือ AI ยืนยันไม่ได้ 100% ว่าสลิปเป็นของจริง เพราะสลิปปลอมทำ QR และตัวอักษรเลียนแบบได้ ข้อ 4 เป็นขั้นเดียวที่ยืนยันว่าโรงเรียนได้รับเงินแล้ว

ค่า `ยืนยันอัตโนมัติเมื่อสลิปถูกต้อง (ไม่แนะนำ)` = TRUE จะข้ามข้อ 4 ไม่แนะนำให้เปิด

### (ทางเลือก) อ่านสลิปด้วย Claude API
ระบบทำงานครบโดยไม่ต้องใช้ ถ้าใส่คีย์ ระบบจะส่งภาพสลิปให้ Claude อ่านคู่กับ OCR ทุกใบ
- **ช่วยอะไร**: อ่านเลขบัญชี ยอดเงิน วันเวลาโอน และเลขอ้างอิงในส่วนที่ OCR อ่านไม่ได้ (รายการจึงไปถึง "รอยืนยันยอดเข้า" และกระทบยอดอัตโนมัติได้มากขึ้น), บอกว่าภาพเป็นสลิปโอนเงินจริงหรือไม่ และสังเกตร่องรอยการแก้ไขภาพ ถ้าพบจะเป็น "รอตรวจ"
- **ไม่ได้ทำ**: ไม่ทำให้รายการเป็น "ยืนยันแล้ว" เอง การยืนยันยังมาจากการกระทบยอดกับรายการเงินเข้า
- **ใส่คีย์**: สร้างคีย์ที่ https://console.anthropic.com (ต้องเติมเครดิตก่อนใช้) แล้วไปที่ **Apps Script → การตั้งค่าโปรเจกต์ → คุณสมบัติของสคริปต์ → เพิ่ม** ชื่อ `ANTHROPIC_API_KEY` ค่าเป็นคีย์ จากนั้นเมนู **Pre Prot Test → ทดสอบการเชื่อมต่อ Claude API**
  คีย์เก็บในคุณสมบัติของสคริปต์เท่านั้น ห้ามใส่ใน Sheet ใน repo หรือในไฟล์อื่น ผู้ที่แก้ไขโปรเจกต์ Apps Script ได้จะเห็นคีย์นี้
- **เลือกโมเดล**: แท็บ ตั้งค่า → `โมเดล Claude (ใช้เมื่อใส่ ANTHROPIC_API_KEY)`

| โมเดล | ค่าใช้จ่ายโดยประมาณต่อสลิป | ต่อ 100 สลิป |
|---|---|---|
| `claude-opus-5-5` (ค่าเริ่มต้น อ่านแม่นที่สุด) | 0.015–0.025 ดอลลาร์ (ประมาณ 0.5–0.9 บาท) | ประมาณ 50–90 บาท |
| `claude-sonnet-5-5` | 0.008–0.013 ดอลลาร์ (ประมาณ 0.3–0.5 บาท) | ประมาณ 30–50 บาท |
| `claude-haiku-5-5` (ถูกที่สุด) | ไม่ถึง 0.001 ดอลลาร์ (ประมาณ 0.03 บาท) | ประมาณ 3 บาท |

  ประมาณจากภาพสลิปที่ระบบย่อเหลือด้านยาว 1,600 พิกเซล ราคาต่อโทเค็นของ Anthropic (Opus 5.5 4/20, Sonnet 5.5 2/10, Haiku 5.5 0.10/0.50 ดอลลาร์ต่อล้านโทเค็น ขาเข้า/ขาออก) และอัตราแลกเปลี่ยนราว 33–36 บาทต่อดอลลาร์ ค่าจริงดูได้ที่หน้า Usage ของ Console การกด "ตรวจสลิปอัตโนมัติอีกครั้ง" คิดเงินเพิ่มอีกครั้ง
- **ข้อมูลส่วนบุคคล**: ภาพสลิป (มีชื่อผู้โอนและเลขบัญชีบางส่วน) ถูกส่งไปประมวลผลที่ Anthropic เมื่อใส่คีย์แล้ว ใบสมัครจะเพิ่มข้อความยินยอมเรื่องนี้ให้อัตโนมัติ
- ถ้าคีย์ผิด เครดิตหมด หรือเรียกไม่สำเร็จ ระบบยังตรวจด้วย OCR ตามปกติ และบันทึกสาเหตุในคอลัมน์ `ผลอ่านด้วย Claude`
- ปิดการใช้งาน: ลบ `ANTHROPIC_API_KEY` ออกจากคุณสมบัติของสคริปต์

## ข้อมูลส่วนบุคคล
- ข้อมูลผู้สมัครและสลิปอยู่ใน Google Sheet และ Google Drive ของบัญชีที่ติดตั้งเท่านั้น
- เว็บไซต์ (repo นี้) ไม่มีข้อมูลรายบุคคล API ส่วนกลาง (`info`) ส่งเฉพาะจำนวนรวม ไม่ส่งรายชื่อ
- ผู้สมัครเข้าระบบด้วยเลขประจำตัวประชาชนหรือเลขที่สมัคร คู่กับเบอร์โทรศัพท์ที่ใช้สมัคร เห็นเฉพาะข้อมูลของตนเอง เลขประจำตัวประชาชนแสดงแบบปิดบางหลัก
- กรอกผิด 8 ครั้งใน 15 นาที ระบบระงับการเข้าระบบของเลขนั้นชั่วคราว
- ผู้ปกครองต้องกดยินยอมการใช้ข้อมูลก่อนส่งใบสมัคร

## เมื่อแก้ไขโค้ด
- เว็บไซต์: แก้ไฟล์ใน repo แล้ว Commit + Push
- ใบสมัครและตัวกลาง: วางโค้ดใหม่ในหน้าแก้ไขสคริปต์ แล้ว **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → แก้ไข (ดินสอ) → เวอร์ชัน: เวอร์ชันใหม่ → ทำให้ใช้งานได้** (ลิงก์เดิมใช้ต่อได้ QR บนโปสเตอร์ไม่ต้องเปลี่ยน)
- หลังแก้ `apps-script/Index.html` ให้รัน `node dev/build-demo.js` เพื่ออัปเดต `form-demo.html`

## ทดสอบโค้ด (สำหรับผู้พัฒนา)
```
node dev/run-tests.js
```
ทดสอบ `Code.gs` ด้วยข้อมูลจำลองทั้งหมด (ไม่เชื่อมต่อ Google) ครอบคลุมการอ่าน QR และข้อความบนสลิป การสมัคร สลิปซ้ำ การเข้าระบบ การกระทบยอด การจัดที่นั่ง การคิดคะแนน และการอ่านสลิปด้วย Claude (จำลองการตอบกลับ ไม่เรียก API จริง)
